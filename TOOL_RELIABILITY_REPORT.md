# Jarvis v6 — Tool Reliability Report

**Principle:** no fake success, no silent failure. A tool returns success only
after verifying the real-world outcome it can observe; otherwise it returns an
`ERROR:` string the pipeline surfaces honestly.

Generated by `python scripts/reliability_report.py` + manual verification of the
v6 delegated tools (which the static auditor can't trace through).

## Summary

`14 verified · 0 fake-success · 5 partial · 4 unknown(delegated)` — **0 critical
gaps**. Orchestrator retry loop: yes. Broad error detection: yes.

## Per-tool status

| Tool | Verifies | How |
|------|----------|-----|
| `open_app` | ✅ (v6) | delegates to `app_launcher`: exit-0=launched, nonzero/FileNotFound=error, missing candidate=honest "not installed" |
| `open_url` | ✅ (v6) | checks `webbrowser.open()` return; honest error when no system browser |

| `run_code/run_tests/check_syntax` | ✅ | real exit codes / `ast.parse` |
| `run_terminal` | ✅ | returns real stdout/stderr + exit code |
| `click/type_text/press_keys/move_mouse` | 🟡 partial | propagate exceptions as ERROR; cannot verify the *visual* effect without vision — honest about it |
| `screenshot` | 🟡 partial | propagates capture errors; can't assert content |

**"unknown(delegated)"** in the static auditor = `open_app`, `open_url`,
`search_google`, `install_package`. The first two *do* verify (above); the
auditor just can't follow the delegation/branching. `search_google` returns real
results or an explicit "No results"; `install_package` surfaces pip's exit code.

## Honest limitations

- GUI-effect verification (did the click actually do the thing?) requires a
  vision pass; `click/type/press` verify the *call* not the *effect*. Marked
  PARTIAL on purpose — they never claim more than they can prove.
- `open_app`/`open_url` runtime success on Windows/desktop can only be fully
  confirmed on that hardware; logic + semantics are unit-tested here.
